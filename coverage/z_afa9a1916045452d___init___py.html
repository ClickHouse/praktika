1"""AI advisor for the orchestrator (skeleton). 

2 

3The orchestrator drives an ``AIAssist`` through the run's lifecycle. As the 

4workflow state advances (job results land), the advisor classifies what changed 

5and routes it to the matching **provider hook** — ``on_job_failure`` when a job 

6fails, ``on_job_success`` when one passes, plus ``on_run_start`` / 

7``on_run_finish`` around the run. Each hook either consults the model and 

8returns a ``Turn`` (reasoning + decision + token usage + cost, which the advisor 

9records) or is the provider's inherited no-op (returns ``None`` → no model call, 

10nothing recorded). So a green run is free: only ``on_job_failure`` is wired to a 

11model today. 

12 

13Decisions are recorded, and the actionable ones are dispatched: ``cancel_run`` 

14flags the run cancelled and the orchestrator loop tears it down; 

15``cancel_and_patch`` applies the model's edits, commits + pushes them via the 

16injected patcher (triggering a fresh run), and cancels the superseded run. 

17The default provider is ``mock``, which does nothing. Disabled by default 

18(``Workflow.Config.ai_assist.enabled``). 

19 

20Real providers (``anthropic`` / ``bedrock-anthropic``) implement ``on_job_failure`` only, 

21running a tool-use loop so the model can investigate the failure before deciding 

22— reading the job's logs (``fetch_log``, restricted to URLs in the observation) 

23and the checked-out PR source (``grep_repo`` / ``read_file``, rooted at the repo). 

24"""

304def _apply_edits(edits, root=None): 

305 """Apply ``[{path, search, replace}]`` edits to files under ``root``. 

306 

307 Each ``search`` must occur **exactly once** in its file; multiple edits to 

308 the same file compose in order. Validation is all-or-nothing: every edit is 

309 checked (path inside repo, file exists, search unique) before anything is 

310 written, so a bad edit leaves the tree untouched. Returns 

311 ``(ok, files, patch_text, error)`` — on success ``files`` is the sorted list 

312 of changed repo-relative paths and ``patch_text`` a unified diff for the 

313 session log; on failure ``ok`` is False and ``error`` says why. 

314 """

316 if not isinstance(edits, list) or not edits: 

317 return False, [], "", "no edits provided"

321 for i, e in enumerate(edits): 

322 if not isinstance(e, dict): 322 ↛ 323line 322 didn't jump to line 323 because the condition on line 322 was never true

323 return False, [], "", f"edit #{i} is not an object" 

324 rel = e.get("path") or "" 

325 search = e.get("search") 

326 replace = e.get("replace") 

327 if not rel or not isinstance(search, str) or not search or not isinstance(replace, str): 327 ↛ 328line 327 didn't jump to line 328 because the condition on line 327 was never true

328 return False, [], "", f"edit #{i} missing path/search/replace" 

329 target = _safe_join(root, rel) 

330 if target is None: 

331 return False, [], "", f"edit #{i} path escapes repo: {rel!r}" 

332 if not os.path.isfile(target): 

333 return False, [], "", f"edit #{i} no such file: {rel!r}" 

334 if target not in current: 

335 try: 

336 with open(target, "r", encoding="utf-8") as f: 

337 text = f.read() 

338 except Exception as ex: 

339 return False, [], "", f"edit #{i} cannot read {rel!r}: {ex}" 

340 originals[target] = text
