189def _s3_statements(prefixes, sid_base, object_actions, list_actions): 

190 """Build split object-level and bucket-level (list) S3 policy statements. 

191 

192 Object actions are scoped to object ARNs; ``s3:ListBucket`` and the other 

193 bucket-level actions are granted per bucket with an ``s3:prefix`` condition 

194 when the allowance is prefix-scoped, so listings cannot escape the prefix. 

195 """ 

196 object_resources, bucket_conditions = _s3_grants(prefixes) 

197 statements = [] 

198 if object_resources: 

199 statements.append( 

200 { 

201 "Sid": f"{sid_base}Objects", 

202 "Effect": "Allow", 

203 "Action": object_actions, 

204 "Resource": object_resources, 

205 } 

206 ) 

207 for i, bucket_arn in enumerate(sorted(bucket_conditions)): 

208 prefixes_cond = bucket_conditions[bucket_arn] 

209 if prefixes_cond is None: 

210 # Whole-bucket grant: no prefix condition, so every list action is 

211 # granted unconditionally. 

212 statements.append( 

213 { 

214 "Sid": f"{sid_base}List{i}", 

215 "Effect": "Allow", 

216 "Action": list_actions, 

217 "Resource": bucket_arn, 

218 }

220 continue

224 # StringLike s3:prefix condition they evaluate false and are silently 

225 # denied. Split them into an unconditional bucket-resource statement. 

226 prefix_aware = [a for a in list_actions if a in _S3_PREFIX_AWARE_ACTIONS]

250@dataclass 

251class RunnerPool: 

252 """A self-contained CI runner pool: one LaunchTemplate, AutoScalingGroup, 

253 and SQSQueue that together form a single runner type. 

254 

255 The ASG always starts with min_size=0; `size` sets the desired capacity 

256 and `max_size` caps the pool. When auto-scaled, `capacity_reserve` keeps 

257 that many extra idle instances above the queue demand. The queue name 

258 matches the `runs_on` label 1:1 so praktika routes jobs without extra 

259 configuration. 

260 

261 The pool assumes the selected AMI already contains the Praktika runner 

262 runtime and systemd unit. By default it enables `praktika-controller` at 

263 boot; `user_data` can override that when extra instance boot customization 

264 is required. 

265 

266 Runtime SSM Parameter Store, Secrets Manager, and S3 access are opt-in 

267 through `allowed_ssm_parameters`, `allowed_secrets`, and 

268 `allowed_s3_prefixes` (read+write); `allowed_s3_prefixes_readonly` grants 

269 read-only S3 access (GetObject/ListBucket, no writes). Bare names are 

270 project namespaced by CloudInfrastructure.Config; full ARNs are preserved 

271 as-is. Each resource type also has an explicit `allow_all_*` escape hatch. 

272 

273 SSM debugging is opt-in through `allow_ssm_debug`. When enabled, the 

274 runner instance role gets only the instance-side SSM Agent permissions 

275 needed to register, receive commands/sessions, and reply. It still cannot 

276 issue SSM commands or start sessions against any runner. 

277 

278 `ext["system_logs"]` (truthy) tags instances so the baked 

279 praktika-system-logs streamer runs at boot, shipping kernel/OOM/systemd-kill 

280 evidence to the `/{slug}/praktika-system` CloudWatch log group. Off by 

281 default; see docs/logging.md. 

282 

283 `ext["iam_statements"]` (list of IAM policy statement dicts) are appended to 

284 the runner instance role's RunnerAccess inline policy, so a project can grant 

285 pool-specific permissions (e.g. a code-review pool's `bedrock:InvokeModel`) 

286 without editing this shared class. Applied only when the role is created here 

287 (not when a custom `ec2_role` is supplied). 

288 

289 All three AWS components are created at construction time and registered 

290 into CloudInfrastructure.Config automatically via its runner_pools list. 

291 

292 Example:: 

293 

294 pool = RunnerPool( 

295 name="arm-small", 

296 instance_type="m8g.2xlarge", 

297 ami_id="ami-...", 

298 security_group_ids=["sg-..."], 

299 vpc_name="ci-cd",

301 size=1, 

302 max_size=2, 

303 volume_size_gb=100, 

304 )
